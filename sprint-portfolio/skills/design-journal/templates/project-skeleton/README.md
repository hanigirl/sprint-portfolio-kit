# תיקיית הפרויקט שלך — יומן העיצוב

זאת לא רק תיקיית קבצים. זאת **יומן ההחלטות** שלך לאורך הספרינט, והוא מה שיהפוך בסוף לתיק העבודות.
החוק האחד: **מתעדים החלטה כשהיא נופלת, לא בסוף.** מה שלא נתפס עכשיו — נעלם, וגם הסוכן לא יוכל לשחזר אותו.

## מבנה
```
brief.md        ← אתגר הספרינט: הבעיה, המשתמש, המדד שרוצים להזיז.
resources/      ← רקע: מוצר, פרסונה, מתחרים/בנצ'מרק, מותג. חומר שלא החלטת אתה אבל חשוב להקשר.
research/       ← מה למדת: סיכומי בדיקות משתמשים, ראיונות, ציטוטים, ממצאים (החומר האיכותני).
decisions/      ← רשומת החלטה אחת לכל צומת (001-*.md, 002-*.md …).
                  כל החלטה שנבחרה, כל כיוון שנפסל, כל פיבוט.
versions/       ← v1/ v2/ … — המסכים/הארטיפקטים לכל איטרציה + הערה קצרה מה השתנה.
metrics/        ← המספרים היבשים: before/after + מקור (test/analytics/sales).
journal.md      ← ציר זמן/אינדקס שנבנה אוטומטית. לא לערוך ביד.
```
**הכלל:** כל חומר — סיכום בדיקה, רקע מוצר, לינק, מסמך — נכנס *לתוך* התיקייה הזאת, בתת-התיקייה
המתאימה. קובץ שיושב מחוץ לתיקייה לא קיים מבחינת הסוכן. תיקייה אחת לפרויקט, לא קבצים מפוזרים.

## איך מתעדים החלטה
הכי פשוט: `/log-decision` (או לבקש מהסוכן "תעד את ההחלטה הזאת"). הוא ישאל אתכם כמה שאלות
קצרות וייצור קובץ ב-`decisions/`. אפשר גם להעתיק את תבנית רשומת ההחלטה ולמלא ביד.

## בסוף הספרינט
`/build-portfolio` (או סקיל `sprint-portfolio`) יסרוק את כל התיקייה הזאת ויבנה **דף case-study**
מוכן-לפורטפוליו: הסיפור, הכיוונים שנפסלו ולמה, הפיבוטים, והזזת המדדים.
